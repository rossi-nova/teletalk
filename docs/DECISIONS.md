# 决策记录

## ADR-001 不走钉钉开放平台，改为代理客户端

**背景**：开放平台的企业内部应用机器人拿不到任意会话历史消息，且需要给自己开应用、配机器人，形态受限。

**决定**：代理钉钉手机客户端的私有协议，网关冒充客户端收发。

**代价**：协议无稳定性承诺，钉钉升级即需重抓；有风控风险。维护成本高，但能力上限高（可拉历史、可群聊、可多媒体）。

## ADR-002 协议蓝本取手机 App，而非 Web 版

**依据**：钉钉网页版 `im.dingtalk.com` 已下线，只剩系统维护页（已核实）。

## ADR-003 前端深改 telegram-tt

**依据**：`Ajaxy/telegram-tt` 是 Telegram Web A，数据层集中在 `src/api/gramjs/methods/*.ts`，UI 按领域函数调用，替换点单一。

**做法**：新建 `src/api/teletalk/`，保持 `methods/*.ts` 同名导出，只换实现。

**许可**：上游 GPL-3.0，无附加条款；强 copyleft，对外分发须整体开源。本项目按 GPL-3.0 发布。

## ADR-004 首版覆盖群聊 + 多媒体

单聊文本 MVP 之后直接进群聊与媒体，不做分批压缩。

## ADR-005 媒体自建 fileId，不追求 MTProto 互通

前端只需要「能取到文件」，无需与 Telegram 星际兼容。
