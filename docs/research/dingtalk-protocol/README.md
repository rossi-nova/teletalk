# 钉钉私有协议研究

本目录记录「代理钉钉手机客户端」所需的协议事实来源。所有结论必须能对应到 `../fixtures/` 中的报文样本，禁止凭印象填写。

## 前提

- 钉钉网页版 `im.dingtalk.com` 已下线（2025—2026 年间变为系统维护页），Web 代理路线不可行。
- 钉钉 Linux 官方客户端仍在维护（AUR `dingtalk-bin`，9.0.0.261105002，2026-11 更新；deb 直链位于 `dtapp-pub.dingtalk.com`）。可用于对照设备字段与请求头，但**手机端仍是协议蓝本**。
- 本项目只使用使用者自己的账号与设备；不提供、不集成绕过平台安全机制的破解工具。

## 每条样本必须记录

1. 请求方法与 URL（域名保留，路径参数脱敏）
2. 请求头全集（凭据字段只记结构，不记原值）
3. 请求体结构（字段名、类型、是否加密）
4. 响应体结构
5. 与上一条同类请求的差异（时间戳、nonce、签名）
6. 判定：Node 侧可复现 / 需额外信息 / 不可复现

## 待判定的关键问题

- 签名是否依赖设备密钥（若依赖，需评估能否用登录时下发的设备凭证替代）。
- 下行通道是否可并发多端（同一账号在两个客户端是否会互相顶下线）。
- 消息 ID 是否由客户端生成（决定发送重试的幂等性）。
